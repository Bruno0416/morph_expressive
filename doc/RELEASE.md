# Publishing checklist: Morph Expressive 0.5.0

**Release candidate — do not publish until the matrix and new GIF captures pass.**

0.5.0 is the minor feature release after 0.4.1: navigation bar/rail/drawer
Morph variants, expressive floating frosted navigation, a page indicator,
selection-timing controls, scroll/glass performance improvements and refresh
polish. Public constructors are additive; existing Material-flavored defaults
are preserved. The root version and README installation example target 0.5.0;
change the CHANGELOG entry from `Unreleased` to the publication date only after
all release checks pass;
`preview/` remains a separate unpublished application.

## 1. Complete compatibility validation

The latest/lowest test matrix must pass **both** lanes. `dart format
--output=none --set-exit-if-changed` reports a nonzero exit when it detects
changes, so a log ending after `Formatted ... (8 changed)` does **not** show a
successful matrix. Fix formatting on the working tree first:

```bash
dart format lib test example preview/lib preview/test
set -o pipefail
bash tool/check_dependency_matrix.sh all 2>&1 | tee /tmp/morph-dependency-matrix.log
```

Confirm that both `Morph dependency resolution: latest` and `lowest` appear,
and each runs `tool/check.sh` (root/preview analysis and tests) and a release
Web build. `flutter pub downgrade` and `upgrade` verify the lowest/latest
**resolvable** versions allowed by the manifest, not every combination.
Compare Android rendering of glass navigation on an emulator and preferably a
physical device in profile; Flutter Web can have a different blur cost.

## 2. Produce two new Flutter-rendered GIFs

Keep `doc/assets/gifs/navigation.gif` unchanged (MD3E). The capture source for
both new scenes lives in `preview/lib/component_gif_capture.dart`:

```bash
bash tool/generate_component_gifs.sh --only navigation_morph --only navigation_rail_drawer
python3 tool/check_gif_branding.py
```

Run the preview test correctly from its own directory:

```bash
(cd preview && flutter test test/gif_capture_test.dart)
```

Inspect the two rendered clips at 640×520 and 640×500, ensuring no overflow,
cutoff, missing glyphs or incorrect selection timing. Add the generated binary
assets to the release commit with their README/pubspec references. The text
`.patch` sets up reproducible capture scenes but **cannot** embed Flutter-rendered
assets unless they have first been generated by the SDK.

## 3. Verify release metadata and archive

```bash
flutter analyze
flutter test
(cd preview && flutter analyze && flutter test)
git diff --check
python3 tool/check_gif_branding.py
dart pub publish --dry-run
```

Check README, navigation guide, CHANGELOG, ten screenshot assets, dependency
constraints, `LICENSE`, `NOTICE` and `.pubignore`. The root `pubspec.yaml`
must say `version: 0.5.0`. Do not mistake the 0.4.1 test counts for new
release evidence. Verify on pub.dev that 0.5.0 is not already published.

## 4. Publish and tag only after gates pass

Review the repository workflows first to avoid triggering duplicate automatic
publication. Then commit/push verified source and new GIF binaries and publish
using the project's existing release process, for example:

```bash
git add pubspec.yaml README.md CHANGELOG.md doc/ lib/ test/ preview/lib/ preview/test/ tool/
git diff --cached --check
git commit -m "release: morph_expressive 0.5.0"
git push origin main
dart pub publish --dry-run
dart pub publish
git tag -a v0.5.0 -m "Morph Expressive v0.5.0"
git push origin v0.5.0
```

Replace commands with the repository's tag-driven release workflow when one
exists. Never republish or overwrite an existing pub.dev version.
